App pools are configured:
{{- range $appName, $app := .Values.github.apps }}
{{- if $app.instances }}
{{- $strategy := (($app.rotation | default dict).strategy) | default "round_robin" }}
  - {{ $appName }}: {{ len $app.instances }} GitHub App instance(s), rotation
    strategy "{{ $strategy }}"
{{- if eq $strategy "rate_limit_aware" }}
    A member whose installation is known to be below {{ (($app.rotation | default dict).minRemainingPct) | default 0 }}% remaining, or out
    of requests, is tried after the others; each skip counts in
    githubsts_app_pool_selection_total{outcome="skipped_rate_limited"}.
{{- end }}
{{- end }}

  Every instance in a pool must be installed with identical permissions and
  repository access. A mismatched instance surfaces only as intermittent 422s.
  Requires a github-sts image that knows instances:, meaning 0.1.1 or later,
  which is what this chart's appVersion pins. An older image rejects the key and
  the pod CrashLoopBackOffs with "field instances not found in type
  config.AppConfig". It does not fall back to the flat form.
  Alert on githubsts_app_pool_exhausted_total: it fires when every instance in
  a pool failed one request.
{{- end }}

{{- if include "github-sts.azureSignerEnabled" . }}

App keys stay in Azure Key Vault: github-sts signs App JWTs there and holds no
private key. It exchanges a projected ServiceAccount token for each cloud
identity a key names, so no Azure secret exists.
{{- $identities := include "github-sts.azureIdentities" . | fromYamlArray }}
  Each identity needs a federated credential with:
    issuer:   this cluster's service account issuer URL
    subject:  system:serviceaccount:{{ .Release.Namespace }}:{{ include "github-sts.serviceAccountName" . }}
    audience: api://AzureADTokenExchange
  Identities:
{{- range $identities }}
    {{ .name }}: client ID {{ .clientId }}, tenant {{ .tenantId }}
{{- end }}
  Each identity needs the sign permission on its own keys and nothing else,
  each key's vault must be in its identity's tenant, and the vault firewall
  must admit the address the pod calls from. github-sts signs a first App JWT
  at startup and refuses to start when a key cannot sign, so a wrong role,
  key, tenant or federated credential shows in the pod log, not in a failed
  exchange:
    kubectl logs -n {{ .Release.Namespace }} deploy/{{ include "github-sts.fullname" . }}
  Requires a github-sts image that knows cloud_identities, meaning 0.1.3 or
  later. An older image rejects the keys and the pod CrashLoopBackOffs with
  "field signer not found in type config.AppConfig".

  networkPolicy.native.cidrs, or the pod cannot sign and never becomes ready.
{{- end }}
{{- end }}
